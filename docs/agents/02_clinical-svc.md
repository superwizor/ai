# clinical-svc

> Read [`00_GLOBAL_CONTEXT.md`](./00_GLOBAL_CONTEXT.md) first.

## Mission

The **core of the product**. Owns patient files, sessions, modalities, therapist reports (read-only from client), and the speaker-label rebuild flow. Most Flutter user actions hit this service. It's also the consumer that calls `billing-svc.CheckQuota` before allowing new sessions.

## Status (2026-05-07)

- **Phase 1 — DONE.** Patient files, modalities, sessions list/details, deployed at `https://clinical-svc-...run.app`.
- **Phase 2 — partial.** `UpdateSpeakerLabels` (rebuilds canonical transcript blob with new labels) is wired and lints clean. Report read endpoints implemented.
- **Feedback domain** (`report_feedback`, `feedback_categories`) — schema in `docs/03_DATA_MODEL.md` §4.9 (v4.2); not yet implemented.

### Critical schema notes

- **Reports come in two flavors**: `therapist_reports` (full clinical detail, encrypted) and `patient_views` (sanitized, separate row, separate ciphertext). Per ADR-DM-008 they are physically separate tables — don't add a JOIN that crosses the boundary in app code without thinking.
- **`speaker_label_mapping JSONB`** on `sessions` is the canonical mapping `{"1": "Osoba 1", "2": "Osoba 2"}` (per ADR-IMPL-002). Generated by `pkg/i18n/speakerlabels.Generate(langCode, tag)`.
- **`transcript_ciphertext`** on `transcripts` is **the source of truth** (ADR-IMPL-006). `transcript_segments` are derived. When the therapist updates speaker labels, you MUST rebuild the canonical blob — see `internal/adapters/grpc/labels.go::UpdateSpeakerLabels`.

## Auth model

**Inbound (Flutter):** Firebase ID token in `authorization: Bearer ...`. Cloud Run public; first thing handlers do is call `identity-svc.ValidateToken` (or read forwarded `UserContext` from gRPC metadata once that flow is wired).

**Outbound:**
- `identity-svc.ValidateToken` / `CheckPermission` (or local cache).
- `billing-svc.CheckQuota` before allowing new sessions/uploads.
- Cloud SQL via VPC connector.
- KMS for envelope decryption when reading encrypted columns.

## Key dependencies

- `identity-svc` (auth + RBAC)
- `billing-svc` (quota gate before sessions/uploads)
- Cloud SQL
- KMS (`pkg/cryptobox` to decrypt PHI columns)

## Constraining ADRs

| ADR | What it forces |
|---|---|
| ADR-DM-002 | All PHI columns are envelope-encrypted (`*_ciphertext` + `*_encrypted_dek`) |
| ADR-DM-005 | M:N therapist↔patient via `therapist_patient_relations` |
| ADR-DM-008 | Patient-facing data physically separated into `patient_views` |
| ADR-DM-010 | All FKs `ON DELETE RESTRICT` — explicit cascades only |
| **ADR-IMPL-002** | Speaker labels are neutral + localized (use `pkg/i18n/speakerlabels`); never embed role assumptions in clinical-svc |
| **ADR-IMPL-006** | `transcripts.transcript_ciphertext` is canonical; segments are derived |
| **P4** (read-only on AI reports) | NEVER add a `WriteReport`-style endpoint here. Reports are only written by `ai-pipeline-svc`'s llm-worker |

## Iteration guardrails

**Safe to change:**
- Add list/get/filter endpoints over existing tables.
- Add new sqlc queries.
- Add feedback endpoints (the schema is already in `docs/03_*.md` §4.9; just not yet implemented).
- Refactor permission caching once the spec is firmed up.

**Careful — touches the canonical blob:**
- Anything that writes `transcripts.transcript_ciphertext` MUST go through the same encrypt path. The blob format is JSON lines with `chunk_idx`, `text`, `start_ms`, `end_ms`, `word_count`, `confidence`, `speaker_tag`, `speaker_label` — see `cmd/stt-worker/main.go::BlobLine` in ai-pipeline-svc for the canonical struct.
- Speaker label changes via `UpdateSpeakerLabels` → must update both `transcript_segments.speaker_label` AND `sessions.speaker_label_mapping` AND rebuild the blob in one transaction. See `labels.go` for the working pattern.

**Don't touch without architecture review:**
- Adding a `WriteReport`/`UpdateReport` endpoint — violates P4.
- Crossing the patient-view ↔ therapist-report boundary in app logic — violates ADR-DM-008.
- Embedding speaker role detection here (e.g., "guess that speaker_tag=1 is therapist") — violates ADR-IMPL-002. Roles are inferred by llm-worker only.

## Common gotchas

- **Reading PHI without decryption:** every `*_ciphertext` column needs `crypto.Decrypt(ctx, ct, dek)`. Forgetting this → returning raw bytes to client → bug + leak.
- **Implicit JOIN to `patient_views`** when querying `therapist_reports` — they're parallel tables, not related rows. Don't merge them.
- **Soft delete:** `WHERE deleted_at IS NULL` on `sessions`, `patient_files`, `users` — easy to forget on new queries.
- **`UpdateSpeakerLabels` race:** if two therapists edit the same session concurrently, the blob rebuild can race. Today we lock via the open transaction; if you ever break that out into separate calls, add `revision_number` optimistic locking (pattern from ADR-DM-007).
